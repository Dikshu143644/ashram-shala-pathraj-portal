The three fixes from v1 are in place and working correctly.

## Role dropdown dismiss gap

In `Header.tsx`, the role switcher dropdown is controlled by:

```tsx
const [roleDropdownOpen, setRoleDropdownOpen] = useState(false);
```

The dropdown closes when the user clicks the toggle button again or selects a role. There is no `onBlur`, no click-outside ref, and no transparent backdrop. On desktop this means the dropdown lingers until explicitly dismissed; on mobile where the dropdown overlaps other UI, it can obscure navigation. A `useEffect` with a document click listener or a simple `<div className="fixed inset-0" onClick={close} />` behind the dropdown would fix it.

## Tab switch effect timing

The `useEffect` in `AppContent` that redirects to the first visible tab runs after render, meaning on a role switch where the current tab becomes invisible, React renders `renderContent()` once with the stale `activeTab` (hitting the `default` case which returns `<AdmissionPortal />`), then the effect fires and corrects it. The user sees one frame of the wrong content. For a demo this is imperceptible, but a `useMemo`-derived effective tab would avoid the extra render cycle. Not blocking.
