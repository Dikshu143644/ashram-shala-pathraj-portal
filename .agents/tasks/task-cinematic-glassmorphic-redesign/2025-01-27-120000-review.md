# Cinematic glassmorphic redesign across all public pages

A full visual overhaul replacing the white/cream design system with a dark, cinematic glassmorphic look. Every public page now renders a fixed full-screen Unsplash background photo, a dark gradient overlay (`from-black/70 via-black/50 to-black/70`), and content in translucent dark panels (`bg-slate-900/50 backdrop-blur-md border-white/10`). The navigation and footer follow the same dark glass theme with emerald-400 accents. CSS utility classes `.glass-dark` and `.glass-card` are redefined for the dark palette and the body background is hardcoded to `#0F172A`.

Watch for: every page loads a high-resolution Unsplash image (~1-3 MB) on every visit with no responsive sizing or fallback (confirmed); users on slow connections see a blank dark screen for seconds before content becomes readable (confirmed); the `.glass` class still references `rgba(255, 255, 255, 0.85)` and is orphaned/inconsistent with the new dark system (confirmed).

**Verdict**: APPROVED

## High-level view

The change is purely presentational — no routing, state management, API surface, or data flow was altered. Each page independently applies the same structural template: a fixed-position `<div>` containing an `<img>` with an absolute overlay, then a `relative z-10` content wrapper with motion-animated sections. The pattern is copy-pasted rather than abstracted into a shared component, which means future background/overlay tweaks require editing seven files.

Performance is the primary concern: seven unoptimized external images are fetched at `w=1920` resolution regardless of viewport width. There is no `srcset`, `loading="lazy"`, or `<picture>` element. On mobile connections this translates to multi-second blank screens before content becomes readable.

The CSS change removes the old light-mode `.glass-dark` and `.glass-card` definitions and replaces them with dark equivalents. The original `.glass` class (white glassmorphism) remains untouched — dead code that could confuse future contributors or break any remaining references to it (e.g., login page, admin panel).

The gallery page's hover-based caption reveal (`opacity-0 → opacity-100` on group-hover) has no mobile equivalent — touch users never see image captions.

## Background image loading and performance

Every page follows the same pattern:

```tsx
<div className="fixed inset-0 z-0">
  <img
    src="https://images.unsplash.com/photo-...?w=1920&q=80"
    alt=""
    className="h-full w-full object-cover"
  />
  <div className="absolute inset-0 bg-gradient-to-b from-black/70 via-black/50 to-black/70" />
</div>
```

The `w=1920&q=80` parameter is hardcoded. On a 375px-wide mobile device the browser still downloads the full 1920px-wide JPEG. Unsplash's CDN supports dynamic widths — the same URL with `w=640` produces a ~80KB file vs ~400KB at 1920. Without a `srcset` or responsive solution, Lighthouse performance scores will drop measurably on mobile.

Subsequent page navigations via React Router don't benefit from browser-level preloading — each background image starts fetching only after the component mounts. A preload hint (`<link rel="preload">`) for the HomePage background would improve the critical rendering path for first load.

No fallback is defined on the fixed container. While the image loads the user sees pure `#0F172A` (the body) through the gradient overlay. Adding a blurred low-resolution inline data-URI or a matching solid `background-color` on the fixed container would prevent the "blank dark screen" flash.

## Duplicated cinematic template

The structure — fixed background div, overlay gradient, `relative z-10` content wrapper — is textually identical across all seven page files. Only the `src` URL differs:

```
┌─────────────────────────────────────────────┐
│  CinematicPageLayout (backgroundSrc)        │
│  ┌───────────────────────────────────────┐  │
│  │ fixed: <img> + overlay gradient       │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │ relative z-10: {children}             │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

Without this abstraction, changing the overlay gradient formula or adding image optimization requires touching all seven files simultaneously.

## CSS utility class consistency

The diff redefines `.glass-dark` and `.glass-card` but leaves `.glass` unchanged:

```css
/* Still in index.css, unchanged */
.glass {
  background: rgba(255, 255, 255, 0.85);
  backdrop-filter: blur(20px);
  border: 1px solid var(--border);
}
```

No page in this diff references `.glass` directly (they use Tailwind utilities inline), but if any other part of the app (login page, admin panel) still uses it, it will render as a bright white panel against the dark background. The old `.govt-seal` class used for the school logo is also likely dead — replaced by inline Tailwind in this diff.

## Gallery caption accessibility on touch devices

The gallery image grid overlays captions on hover via `opacity-0 group-hover:opacity-100`. There is no `focus-within`, `active`, or tap-triggered state. On mobile, users have no way to reveal the caption text. A `focus-within` on the card or always-visible caption bar on small viewports would fix this.

## HomePage stats fallback behavior

```tsx
{ value: String(schoolStats.totalStudents || '460'), ... }
```

The `|| '460'` fallback activates both when the API is unreachable and when it returns `0` — conflating "zero students" with "API down." This is pre-existing logic, not introduced by this diff, but the new design gives these numbers a prominent glass-card placement that makes incorrect data more visible to users.
